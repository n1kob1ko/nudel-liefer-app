# AGENTS.md

Conventions for coding agents. Source of truth: [`backlog.md`](./backlog.md) (read §0-§6 each session) and [`projektbeschreibung.md`](./projektbeschreibung.md). If they disagree, backlog §2 Decisions wins.

## Workflow (backlog §0)

- One ticket per session: lowest-numbered `todo` ticket whose `depends_on` are `done`.
- Set `in-progress` before starting, `done` only when all acceptance criteria and the Definition of Done pass. Update the §7 index row too.
- Stay in scope; missing things become new tickets. Unspecified details: simplest option consistent with §2, one line in the Decision log (§9). Irreversible actions: mark `blocked` and stop.
- Never commit secrets; config via env vars documented in `.env.example` (and `docs/env.md`).
- Commit message: `NUD-xxx: <title>`.

## Conventions (backlog §4)

- Stack: Next.js App Router, TypeScript strict, pnpm, Prisma + PostgreSQL, Tailwind + shadcn/ui, next-intl, zod, Auth.js v5, Vitest, Playwright.
- Code, identifiers, comments, commits in English; all UI text through next-intl (5 locales: `de`, `en`, `sr-Latn` (Serbian, Latin script), `cs`, `zh-Hans`). The office (admin) screens exist in `de`, `en`, `zh-Hans`; the driver screens in all five. `sr-Latn.json` and `cs.json` carry only the driver namespaces (`common`, `home`, `auth`, `driver`, `pwa`, `errorPages`, `maps`); `pnpm i18n:check` enforces that split and the CLDR plural categories (cs: one/few/many/other, sr: one/few/other). All message files are hand-written; `pnpm i18n:build` only refreshes `src/lib/fatal-messages.json`. Traditional Chinese and OpenCC are gone (D21).
- Layout: `src/domain` (pure logic, no framework imports), `src/server` (db, services, providers), `src/components`, `src/lib`, `tests/e2e`, `docs`.
- Server mutations: zod validation + server-side role check. Providers (geocoder, routing, translator, storage) behind interfaces with a Fake implementation.
- Auth: every server action / route handler starts with `requireRole(...)` from `src/server/auth/guards.ts` (the proxy is not enough); driver mutations use `requireRole("DRIVER")`. A new server action (`"use server"` module export) or `route.ts` handler must get a row in `src/server/authz-matrix.test.ts` (the test enumerates the source tree and fails otherwise); state-changing route handlers call `rejectCrossOrigin` (`src/server/csrf.ts`), read bodies with `readTextLimited`, and every zod string/array on client input needs `.max()` (`input-limits.test.ts`). Security headers / CSP: `src/lib/security-headers.ts`, see `docs/deploy.md` section 11; personal data and retention: `docs/privacy.md`.
- Soft delete only (`active=false`); the two exceptions are the order retention job (NUD-201, below) and deleting a user account (NUD-206: `src/server/user-delete.ts` is the only place a `User` row is removed; a new relation to `User` must be added to `USER_REFERENCES` there, `user-delete.test.ts` fails until it is). Driver UI: touch targets >= 48 px, body >= 16 px.
- Use the glossary in backlog §3 (Tour vs. route, Stop, Release, ...).
- Design system: `DESIGN.md` (colours, buttons, the 20 motion rules) and `PRODUCT.md` (who uses it, where). Yolk (`bg-primary`) is a fill for the one important action, never a text colour; links use the `link` class; motion building blocks are in `src/components/motion`.
- UI kit: shadcn-style components in `src/components/ui` (use `cn` from `src/lib/utils`); shared states `EmptyState`/`ErrorState`/`LoadingSkeleton` in `src/components/shared/states.tsx`; format dates/quantities with `createAppFormatters` (`src/lib/format.ts`). Driver screens use `size="lg"` / `icon-lg` buttons (48 px). New admin pages go under `src/app/[locale]/admin/` (layout guard + `requirePageActor` in the page), driver pages under `src/app/[locale]/driver/(app)/` (the login page stays outside the group).

## Definition of Done (backlog §5)

`pnpm lint && pnpm typecheck && pnpm test && pnpm i18n:check` green (plus `pnpm test:e2e` for UI flows); new UI text in `de` + `zh-Hans`; authorization tests for new mutations; env vars documented; migrations committed; screens checked at 375 px (driver) / 1280 px (admin); implementation notes added under the ticket.

## Content-Security-Policy: no inline scripts (NUD-110)

- Production `script-src` is `'self'` + a per-request nonce + the hashes of the prebuilt shells (`src/proxy.ts`, `src/lib/security-headers.ts`, `docs/deploy.md` section 11.1a). Never add `'unsafe-inline'` / `'unsafe-eval'` to make something work; fix the cause (no `onclick="..."`, no inline `<script>` in `public/*.html`, no `dangerouslySetInnerHTML` scripts; put code in a file or a client component).
- Build with `pnpm build` (two `next build` passes + `scripts/csp-script-hashes.ts check`). `.csp-script-hashes.json` is a git-ignored build artifact. `pnpm dev` keeps the loose development policy, so check script changes against a production build (`security-headers.spec.ts` asserts the strict policy there).

## Monitoring and error pages (NUD-094)

- Sentry is optional and loaded only through dynamic imports behind `SENTRY_DSN` / `NEXT_PUBLIC_SENTRY_DSN` (zero overhead without). Every event goes through `src/lib/sentry-scrub.ts`; never add request bodies, cookies or query strings. The DSN host is added to the CSP `connect-src` by `src/lib/security-headers.ts`.
- New cron/ops routes use the bearer `CRON_SECRET` and need a `SECRET_ONLY` row in `src/server/authz-matrix.test.ts`.
- Audit log (NUD-092/111): append-only. The only delete path is `src/server/audit-retention.ts` (cron `GET /api/cron/audit-retention`), which sets the transaction-local `nudel.audit_retention = 'on'`; the trigger function honours it for `DELETE` of rows older than 90 days only (floor in SQL and `MIN_AUDIT_RETENTION_DAYS`). Never write another `DELETE`/`UPDATE` on `"AuditLog"` (`audit-coverage.test.ts` fails); a new migration touching the trigger function must keep both rules.
- Retention of driver free text (NUD-112): `src/server/data-retention.ts` (cron `GET /api/cron/data-retention`, `DRIVER_TEXT_RETENTION_DAYS` default 365, `DATA_RETENTION_MODE` default `dry-run`) sets only `Stop.problemNote` to NULL on stops completed before the cutoff. This job never deletes orders, tours or stops; that is the order retention job below. A new column that stores free text typed by a driver or the office must be added to `docs/privacy.md` section 6 and, if it is driver text, to this job. The job is exempt from the audit rule (reason in `audit-coverage.test.ts`).
- Each segment has an `error.tsx` (driver, admin, `global-error.tsx`); texts live in `errorPages.*` (global-error reads the generated `src/lib/fatal-messages.json`, rebuilt by `pnpm i18n:build`).
- Deleting settled orders (NUD-201, client decision 2026-11-13): `src/server/order-retention.ts` (cron `GET /api/cron/order-retention`, `ORDER_RETENTION_DAYS` default 30, `ORDER_RETENTION_MODE` default `dry-run`) hard-deletes orders, their stops and tours and the monthly "paid" notes 30 days after they were paid; what is not paid stays, and customers, products, settings, standing tours and standing orders are never touched. The rule "settled" lives in `settledSql`, "what goes together" in `purgeSelection` (`src/domain/order-retention.ts`). A new table that hangs on `Order`, `Stop` or `Tour` needs `onDelete: Cascade` or a step in this job, and a new way to owe money must be added to `settledSql` (otherwise unpaid things get deleted). Never derive a lasting fact from "an order row exists": old orders disappear (that is why `RecurringOrder.generatedCount` counts the deliveries of a standing order and the product unit lock also looks at standing orders). Exempt from the audit rule (reason in `audit-coverage.test.ts`); `docs/audit-and-retention.md`, `docs/privacy.md` section 6.
- Operations: `docs/runbook.md`.

## Deployment and services: Railway (set up 2026-11-13, NUD-202)

- **The app is set up on Railway**: project `routenplanner`, environment `production`, region Europe West. Services: `app` (this repository, Railpack), `Postgres` (18), buckets `photos` and `backups`, and two helpers built from `deploy/railway/`: `cron`, `backup`. **`docs/deploy-railway.md` is the source of truth** for every setting and variable; change it in the same pull request as the setting.
- **A push deploys.** `app` rebuilds on every push to the branch it follows; pre-deploy runs `pnpm db:migrate && pnpm bucket:cors --apply && pnpm bucket:check && pnpm maps:check --warn-only` (the last one asks Google once for an address and a route and prints `ok`/`FAIL` into the deploy log; it never stops a deploy). No SSH, no manual build. A failed build, migration or health check (`/api/health`) leaves the running version in place.
- **No `railway.json` and no `Dockerfile` in the repository root.** Config as Code is deprecated on Railway (new services cannot opt in), and a root Dockerfile would replace the Railpack build of `app`, which needs every service variable at build time (the CSP in `next.config.ts` is built from `S3_*`, `MAP_TILE_URL`, `SENTRY_DSN`).
- **Photos are in a virtual-hosted bucket**: `S3_URL_STYLE=virtual` makes the storage client sign `https://<bucket>.<endpoint host>/<key>` and the CSP allow that host (`src/lib/s3-url-style.ts`). The bucket needs a CORS rule for the app's address (`scripts/set-bucket-cors.ts`, origins from `S3_CORS_ORIGINS`). A new address of the app goes into `S3_CORS_ORIGINS`, otherwise uploads fail in the browser with a CORS error.
- **Cron: one dispatcher, two lists.** `deploy/railway/cron/dispatch.mts` runs every 5 minutes and calls the due `/api/cron/*` routes; its `CRON_JOBS` must equal `vercel.json` (`scripts/railway/cron-dispatch.test.ts` fails otherwise). A new cron route needs a line in both. The file runs under plain Node 22 (type stripping): erasable TypeScript only, no imports from the repository.
- **Backup** is the master-data dump of NUD-200 (`pnpm backup:db`), run by the `backup` service every night into the `backups` bucket. Railway's own volume backups stay off (they would hold orders and payments). The rules for a new Prisma model (`BACKED_UP_TABLES` / `NOT_BACKED_UP_TABLES`) are unchanged.
- **Deleting settled orders is on** on Railway since 2026-11-13 (`ORDER_RETENTION_MODE=delete`, the owner's word; 30 days after the payment, daily at 03:57 UTC). `DATA_RETENTION_MODE` and `ORPHAN_CLEANUP_MODE` stay `dry-run` until the owner asks for `delete`. Never change one of the three without the owner's word: deleted orders do not come back, the backup does not hold them.
- **Maps: Google for search and routes, the map itself stays Leaflet (NUD-203).** `GOOGLE_MAPS_SERVER_KEY` selects `GoogleGeocoder` (`src/server/geocoder/google.ts`) and `GoogleRoutingProvider` (`src/server/routing/google.ts`) and wins over the `ORS_*` / `PHOTON_*` variables. Rules that come from Google's terms for the owner's EEA account and from the price list, each guarded by a test: never hand Google's address text (`formatted_address`) or route steps to the UI (they may not be shown next to a map; the candidate label is what the user typed); never ask `computeRoutes` for more than 10 intermediates, for traffic or for `optimizeWaypointOrder` (a higher price class; the order is the heuristic's); never store Google route results in a cache table; the key never in a URL that is logged, an error text or the health report. CI and e2e run without the key (Fake / heuristic).
- **Checking it:** `GET /api/health` on the Railway address must report `"status":"ok"` with `routing.mode` and `geocoding.mode` both `google`. Every deploy log of `app` shows with two `[maps-check]` lines whether Google really answers; `FAIL` with a valid key points at the billing account first.

## The dedicated server (2026-11-04 until the move to Railway)

The sections below describe the previous home, `65.109.100.79` / <https://nudel.stragas.com>. The owner decided on 2026-11-13 not to use that address any more. Keep the text as the description of what runs there until the server is switched off; do not deploy there.

- **Production is one host: `65.109.100.79`, serving <https://nudel.stragas.com> at the ROOT** (no `/delivery-app/` prefix). Its nginx vhost is `/etc/nginx/sites-available/nudel-stragas`; TLS is Let's Encrypt via `certbot --nginx` (auto-renewing). On that host: the Next.js app (systemd `delivery-app`, `127.0.0.1:3100`), PostgreSQL 18 (db `nudel`), MinIO (Docker, `127.0.0.1:9000`, bucket `nudel-photos`), openrouteservice (`127.0.0.1:8082`), Photon (`127.0.0.1:2322`) and Nominatim (`127.0.0.1:8088`, Photon's data source). **ORS and Photon run on the server itself** — the old dev-PC reverse-SSH tunnel is gone and `deploy/local-services/tunnel.ps1` now refuses to run.
- **Never deploy to `87.106.60.131`.** That vServer was retired on 2026-11-04 and its data migrated. `deploy/deploy.ps1` and `deploy/server-setup.sh` refuse it explicitly.
- **`deploy.bat` is currently unusable against the new host.** `server-setup.sh` builds the obsolete `/delivery-app/` sub-path layout and rewrites `/etc/delivery-app.env`, so it refuses `65.109.100.79` and `nudel.stragas.com` on purpose — deploying it would break the live site. - **Build on the server, never locally.** The Turbopack build inlines pnpm store paths into server chunks, so a `.next` built elsewhere fails with `Cannot find module '@prisma/client-<hash>'`. Never export `NEXT_PUBLIC_BASE_PATH` for this host.
- **Environment:** `/etc/delivery-app.env` (root:deliveryapp, 640). Secrets are generated once there; `ORS_BASE_URL=http://127.0.0.1:8082/ors`, `PHOTON_URL=http://127.0.0.1:2322`, `PHOTON_LANG=de`, `ORS_API_KEY` unset. `/etc/hosts` maps `127.0.0.1 nudel.stragas.com` so the app can reach its own S3 endpoint — removing that line breaks photo upload and the health check's `storage` probe.
- **Checking it:** `curl -s https://nudel.stragas.com/api/health` must report `"status":"ok"` with `routing.mode` and `geocoding.mode` both `self-hosted`. That is a real reachability check on this host (the providers are local), unlike the old tunnel setup. Backups: `nudel-backup.timer` on the server runs `pnpm backup:db` every night (`deploy/backup/install.sh` sets it up); dumps go to `/var/backups/nudel/db/` on the server only and hold **master data only** — never orders, tours, payments or the audit log. A new Prisma model must be put on `BACKED_UP_TABLES` or `NOT_BACKED_UP_TABLES` in `scripts/lib/backup.ts` (`backup.test.ts` fails otherwise); a kept table must not reference a left-out one. `.github/workflows/backup.yml` is skipped unless the optional off-site bucket is configured (`docs/runbook.md` section 5).
